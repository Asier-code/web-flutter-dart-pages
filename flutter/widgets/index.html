    StatefulWidget y StatelessWidget en Flutter¶

    📄 Nota: Esta página, como el resto de contenidos de esta guía, proviene de un fichero de texto Markdown. Puedes encontrarla, editarla y versionarla junto al resto de la documentación sin ninguna complicación. La idea es que la guía crezca y se mantenga actualizada de forma sencilla, igual que el código que documenta.

    Si estás empezando con Flutter, una de las primeras cosas que te encuentras son estos dos tipos de widgets: StatelessWidget y StatefulWidget. Al principio puede parecer un lío, pero en realidad la idea es muy simple.

    La diferencia está en una pregunta: ¿este widget necesita cambiar con el tiempo?

    Si la respuesta es "no", usa StatelessWidget. Si la respuesta es "sí", necesitas StatefulWidget.

    StatelessWidget: lo que no cambia¶

    Un widget sin estado es exactamente eso: una pieza de interfaz que, una vez construida, no va a cambiar por sí sola. Recibe unos datos (normalmente en el constructor), los pinta, y se olvida.

    Piensa en un texto estático, un icono, un botón que siempre hace lo mismo. No hay nada que se actualice internamente.

    Ejemplo mínimo de StatelessWidget¶

    import 'package:flutter/material.dart';

class TarjetaBienvenida extends StatelessWidget {
  final String nombre;
  final String mensaje;

  const TarjetaBienvenida({
    super.key,
    required this.nombre,
    required this.mensaje,
  });

  @override
  Widget build(BuildContext context) {
    return Card(
      child: Padding(
        padding: const EdgeInsets.all(16.0),
        child: Column(
          children: [
            Text(
              '¡Hola, $nombre!',
              style: const TextStyle(fontSize: 20, fontWeight: FontWeight.bold),
            ),
            const SizedBox(height: 8),
            Text(mensaje),
          ],
        ),
      ),
    );
  }
}

    Este widget recibe un nombre y un mensaje, y los muestra dentro de una tarjeta. No hay nada más. No tiene contadores que incrementar, ni checkboxes que marcar. Es pura presentación. Por eso es StatelessWidget.

    Lo importante aquí es que los datos vienen de fuera (a través del constructor) y una vez que se pintan, no hay manera de que el widget cambie por sí mismo. Si los datos cambian desde fuera, Flutter reconstruye el widget con los nuevos valores.

    StatefulWidget: cuando las cosas se mueven¶

    Ahora imagina que quieres un contador que aumente cada vez que pulsas un botón. O un campo de texto donde el usuario escribe algo. O un interruptor que cambia de color cuando lo activas.

    En esos casos, el widget necesita recordar algo que puede cambiar con el tiempo. Eso es el "estado". Y para manejar eso, necesitas StatefulWidget.

    Un widget con estado en realidad son dos clases: - El StatefulWidget (que es inmutable y se puede reconstruir) - La State (que vive más tiempo y guarda los datos que cambian)

    Ejemplo mínimo de StatefulWidget¶

    import 'package:flutter/material.dart';

class Contador extends StatefulWidget {
  const Contador({super.key});

  @override
  State<Contador> createState() => _ContadorState();
}

class _ContadorState extends State<Contador> {
  int _contador = 0;

  void _incrementar() {
    setState(() {
      _contador++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisAlignment: MainAxisAlignment.center,
      children: [
        Text(
          'Has pulsado: $_contador veces',
          style: const TextStyle(fontSize: 24),
        ),
        const SizedBox(height: 16),
        ElevatedButton(
          onPressed: _incrementar,
          child: const Text('Incrementar'),
        ),
      ],
    );
  }
}

    Mira lo que pasa aquí: - _contador es la variable que guarda el estado. Está dentro del State, no en el widget. - Cada vez que quieres cambiar algo que afecta a la interfaz, llamas a setState. - Dentro de setState, actualizas las variables. Flutter entonces vuelve a llamar a build y redibuja lo que haya cambiado.

    Ese setState es el que hace la magia. Sin él, Flutter no sabría que algo ha cambiado y la pantalla no se actualizaría.

    ¿Por qué dos clases para un solo widget?¶

    Esta separación puede parecer extraña al principio. ¿Por qué no podemos tener todo junto?

    La razón es de rendimiento. Flutter puede reconstruir los widgets muchas veces (cada vez que algo cambia en la pantalla). Si el estado estuviera dentro del propio widget, se perdería cada vez que Flutter lo reconstruyera. Al separar el estado en una clase aparte que no se reconstruye, el estado persiste aunque el widget se vuelva a construir.

    Es como tener una nevera (el State) dentro de una casa que puede reconstruirse (el StatefulWidget). La casa puede cambiar, pero la nevera y su contenido siguen ahí.

    Cuándo usar cada uno¶

    La regla general es simple:

    Usa StatelessWidget cuando: - La interfaz depende solo de datos que vienen de fuera y no cambian internamente. - No necesitas que nada se actualice después de pintarse. - Tienes componentes puros como textos, iconos, botones fijos, contenedores.

    Usa StatefulWidget cuando: - Tienes interacción del usuario que cambia algo visible (contadores, checkboxes, formularios). - Necesitas animaciones controladas por código. - El widget responde a cambios en el tiempo (temporizadores, streams, conexiones en tiempo real).

    Un ejemplo más cercano a la vida real¶

    Aquí tienes una pantalla de login que combina ambos tipos. El widget principal es StatefulWidget porque necesita recordar lo que el usuario escribe, pero los widgets internos (como los campos de texto) son StatelessWidget que Flutter ya nos proporciona:

    import 'package:flutter/material.dart';

class PantallaLogin extends StatefulWidget {
  const PantallaLogin({super.key});

  @override
  State<PantallaLogin> createState() => _PantallaLoginState();
}

class _PantallaLoginState extends State<PantallaLogin> {
  final TextEditingController _emailController = TextEditingController();
  final TextEditingController _passwordController = TextEditingController();
  bool _isLoading = false;
  bool _obscurePassword = true;

  Future<void> _iniciarSesion() async {
    setState(() {
      _isLoading = true;
    });

    // Simular llamada a API
    await Future.delayed(const Duration(seconds: 2));

    setState(() {
      _isLoading = false;
    });

    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('Inicio de sesión simulado')),
    );
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Iniciar Sesión'),
      ),
      body: Padding(
        padding: const EdgeInsets.all(24.0),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            TextField(
              controller: _emailController,
              decoration: const InputDecoration(
                labelText: 'Correo electrónico',
                border: OutlineInputBorder(),
              ),
              keyboardType: TextInputType.emailAddress,
            ),
            const SizedBox(height: 16),
            TextField(
              controller: _passwordController,
              decoration: InputDecoration(
                labelText: 'Contraseña',
                border: const OutlineInputBorder(),
                suffixIcon: IconButton(
                  icon: Icon(
                    _obscurePassword
                        ? Icons.visibility
                        : Icons.visibility_off,
                  ),
                  onPressed: () {
                    setState(() {
                      _obscurePassword = !_obscurePassword;
                    });
                  },
                ),
              ),
              obscureText: _obscurePassword,
            ),
            const SizedBox(height: 24),
            _isLoading
                ? const CircularProgressIndicator()
                : ElevatedButton(
                    onPressed: _iniciarSesion,
                    style: ElevatedButton.styleFrom(
                      minimumSize: const Size(double.infinity, 48),
                    ),
                    child: const Text('Entrar'),
                  ),
          ],
        ),
      ),
    );
  }
}

    En este ejemplo: - _emailController y _passwordController guardan lo que el usuario escribe. - _isLoading controla si mostramos el botón o un indicador de carga. - _obscurePassword controla si la contraseña se ve o se oculta. - Cada vez que algo cambia, llamamos a setState para que la interfaz se actualice.

    Lo que es importante llevarse¶

    La distinción entre StatelessWidget y StatefulWidget es uno de los conceptos fundamentales de Flutter:

    • StatelessWidget: inmutable, no cambia una vez construido. Ideal para componentes de presentación.
    • StatefulWidget: mutable, puede cambiar con el tiempo. Usa setState para actualizar la interfaz.
    • El estado vive en la clase State, no en el widget. Eso permite que Flutter reconstruya los widgets sin perder los datos.
    • La regla de oro: si algo puede cambiar en la pantalla, necesita estado.

    Con la práctica, elegir entre uno y otro se vuelve automático. Empiezas a reconocer dónde necesitas setState y dónde simplemente pintas datos que vienen de fuera. ```
