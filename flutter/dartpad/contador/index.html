    App Contador en Flutter¶

    📄 Nota: Esta página forma parte de la sección de ejemplos interactivos de la guía Dart & Flutter. Todo el contenido proviene de ficheros de texto Markdown, lo que permite mantenerlo actualizado y versionado fácilmente.

    Si hay un ejemplo que todo desarrollador Flutter ha visto alguna vez, es el contador. No porque sea espectacular, sino porque es el ejemplo más pequeño posible que demuestra algo realmente importante: cómo Flutter actualiza la interfaz cuando los datos cambian.

    Cuando creas un proyecto nuevo con flutter create, lo primero que aparece es exactamente esto: un número en pantalla y un botón para incrementarlo. Muchos lo borran sin leerlo. Este tutorial hace lo contrario: lo desmonta pieza a pieza para entender qué está pasando y por qué funciona así.

    Qué hace la app¶

    La app es sencilla al máximo:

    • Muestra un número en el centro de la pantalla. Al principio es 0.
    • Tiene un botón flotante con un símbolo + en la esquina inferior derecha.
    • Cada vez que el usuario pulsa ese botón, el número aumenta en uno.
    • La pantalla se actualiza sola para mostrar el nuevo valor, sin recargar nada.

    Eso es todo. Pero dentro de esa sencillez hay tres conceptos clave que están en la base de prácticamente cualquier app Flutter: estado, widgets con estado y reconstrucción de la interfaz.

    Las piezas que intervienen¶

    La variable que guarda el valor¶

    El número que se muestra en pantalla no es un texto estático. Es una variable que vive dentro del widget, llamada _contador. El guión bajo al principio es la convención de Dart para indicar que es privada, es decir, que solo se puede acceder a ella desde dentro de ese mismo fichero.

    Esta variable es el estado de la app. El estado es cualquier dato que puede cambiar con el tiempo y que, cuando cambia, debe reflejarse en la interfaz.

    El widget con estado — StatefulWidget¶

    En Flutter hay dos tipos de widgets: los que nunca cambian (StatelessWidget) y los que pueden cambiar a lo largo del tiempo (StatefulWidget). Un texto fijo en una pantalla de bienvenida puede ser StatelessWidget. Un contador que cambia cada vez que el usuario pulsa un botón necesita ser StatefulWidget.

    Un StatefulWidget está siempre formado por dos clases que trabajan juntas:

    • La clase del widget en sí, que es inmutable y solo describe el tipo de widget.
    • La clase del estado (State), que es donde viven los datos variables y el método build que dibuja la interfaz.

    Puede parecer redundante tener dos clases para una sola pantalla, pero tiene sentido: Flutter separa lo que no cambia (el widget) de lo que sí puede cambiar (el estado).

    El botón flotante — FloatingActionButton¶

    El botón circular que aparece en la esquina inferior derecha es un FloatingActionButton, un widget estándar de Material Design. Se coloca directamente en el Scaffold a través de su propiedad floatingActionButton, por lo que Flutter ya sabe dónde posicionarlo automáticamente.

    Lo importante del botón es su propiedad onPressed: ahí es donde defines qué ocurre cuando el usuario lo pulsa.

    La actualización visual — setState¶

    Aquí está la clave de todo. Cuando el usuario pulsa el botón, el valor de _contador tiene que cambiar. Pero solo con cambiar la variable no es suficiente: Flutter no sabe que algo ha cambiado y no va a redibujar nada por su cuenta.

    Para avisarle, usas setState. Es una función que le dice a Flutter: "algo ha cambiado en el estado de este widget, por favor reconstrúyelo". Flutter entonces llama de nuevo al método build, que genera la interfaz con el nuevo valor de _contador, y el número actualizado aparece en pantalla.

    Este ciclo —el usuario interactúa, el estado cambia con setState, Flutter reconstruye la interfaz— es el patrón más fundamental de toda la gestión de estado en Flutter.

    El código completo¶

    import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: AppContador()));

class AppContador extends StatefulWidget {
  const AppContador({super.key});

  @override
  State<AppContador> createState() => _AppContadorState();
}

class _AppContadorState extends State<AppContador> {
  int _contador = 0; // El estado: el número que se muestra en pantalla

  void _incrementar() {
    setState(() {
      _contador++; // Cambia el estado y avisa a Flutter para redibujar
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Mi Contador'),
        backgroundColor: Colors.indigo,
        foregroundColor: Colors.white,
      ),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            const Text(
              'Has pulsado el botón',
              style: TextStyle(fontSize: 18, color: Colors.black54),
            ),
            const SizedBox(height: 12),
            Text(
              '$_contador', // Se actualiza cada vez que setState se llama
              style: const TextStyle(
                fontSize: 72,
                fontWeight: FontWeight.bold,
                color: Colors.indigo,
              ),
            ),
            const SizedBox(height: 12),
            Text(
              _contador == 0
                  ? 'Empieza pulsando el botón +'
                  : _contador == 1
                      ? '¡Primer clic!'
                      : '¡Sigue así!',
              style: const TextStyle(fontSize: 14, color: Colors.grey),
            ),
          ],
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _incrementar, // Llama a la función que actualiza el estado
        backgroundColor: Colors.indigo,
        child: const Icon(Icons.add, color: Colors.white),
      ),
    );
  }
}

    Por qué este ejemplo importa¶

    El contador puede parecer trivial, pero en realidad está enseñando exactamente cómo funciona Flutter por dentro.

    Toda app, por compleja que sea, se reduce en algún punto a lo mismo: algo cambia (el usuario interactúa, llega un dato de la red, pasa un segundo), el estado se actualiza, y la interfaz refleja ese cambio. Flutter hace esa actualización de forma muy eficiente: no redibuja toda la pantalla, sino solo el widget que ha cambiado.

    Entender el ciclo estado → setState → build → interfaz es entender Flutter. Las soluciones de gestión de estado más avanzadas que verás más adelante, como Provider, Riverpod o Bloc, son esencialmente variaciones de esta misma idea, diseñadas para funcionar mejor cuando el estado es compartido entre muchos widgets o cuando la app tiene mucha complejidad.

    Así que la próxima vez que alguien te diga que el contador es un ejemplo demasiado simple, ya sabes la respuesta: es simple por fuera, pero por dentro explica el corazón de Flutter.
