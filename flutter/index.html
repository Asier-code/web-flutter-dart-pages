    Introducción a Flutter¶

    📄 Nota: Esta página forma parte de la guía completa Dart & Flutter. Todo el contenido proviene de ficheros de texto Markdown, lo que nos permite mantener la documentación versionada, colaborativa y fácil de actualizar con Git.

    Si llevas un tiempo programando con Dart, o simplemente te has interesado por el desarrollo móvil, tarde o temprano acabas aquí: Flutter. Y tiene mucho sentido, porque Flutter es la razón por la que mucha gente aprende Dart en primer lugar.

    Vamos a ver qué es, por qué se ha puesto tan popular tan rápido y cómo está organizada esta parte de la guía para que puedas avanzar con orden y sin perderte.

    ¿Qué es Flutter?¶

    Flutter es el framework de UI de Google para construir aplicaciones nativas desde un único código base. Eso significa que escribes tu app una sola vez y puedes compilarla para:

    • 📱 Android e iOS (móvil)
    • 🖥️ Windows, macOS y Linux (escritorio)
    • 🌐 Web (navegador)

    No es una app híbrida que envuelve una WebView, ni un puente que traduce llamadas a componentes nativos. Flutter tiene su propio motor de renderizado (basado en Skia/Impeller) que dibuja cada píxel de la pantalla directamente. Eso le da un control total sobre el aspecto visual y un rendimiento muy cercano al nativo.

    ¿Por qué Flutter ha crecido tanto?¶

    Hay varios factores que explican su adopción rápida:

    Un solo código para todas las plataformas. No mantienes una app en Swift para iOS, otra en Kotlin para Android y otra en React para web. Todo está en un único proyecto Dart.

    Hot Reload. Cambias una línea de código, guardas, y ves el resultado en el dispositivo en menos de un segundo, sin perder el estado de la app. Es uno de los ciclos de feedback más rápidos que existen en desarrollo de interfaces.

    Todo son widgets. En Flutter, cada elemento visual es un widget: un botón, un texto, un padding, una columna, incluso la propia aplicación. Esto crea un modelo mental muy consistente: si quieres añadir algo a la pantalla, hay un widget para eso.

    Diseño pixel-perfect y consistente. Al renderizar directamente, la app tiene exactamente el mismo aspecto en Android que en iOS, lo que simplifica enormemente el trabajo de diseño y QA.

    Ecosistema maduro. pub.dev tiene miles de paquetes, la comunidad es activa y Google lo usa internamente en apps como Google Pay.

    Tu primera app Flutter — La estructura mínima¶

    Antes de entrar en detalles, veamos cómo es una app Flutter en su forma más simple. Esto es lo primero que ves cuando creas un proyecto nuevo y limpias el código de ejemplo:

    import 'package:flutter/material.dart';

void main() {
  runApp(const MiApp());
}

class MiApp extends StatelessWidget {
  const MiApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Mi Primera App',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
        useMaterial3: true,
      ),
      home: const PantallaInicio(),
    );
  }
}

class PantallaInicio extends StatelessWidget {
  const PantallaInicio({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Bienvenido a Flutter'),
        backgroundColor: Theme.of(context).colorScheme.inversePrimary,
      ),
      body: const Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Icon(Icons.flutter_dash, size: 80, color: Colors.indigo),
            SizedBox(height: 16),
            Text(
              '¡Hola, Flutter!',
              style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
            ),
            SizedBox(height: 8),
            Text(
              'Tu primera pantalla está funcionando.',
              style: TextStyle(fontSize: 16, color: Colors.grey),
            ),
          ],
        ),
      ),
    );
  }
}

    Hay varias cosas que vale la pena notar aunque sea de pasada:

    • runApp es el punto de entrada de toda app Flutter. Recibe el widget raíz y lo pone en pantalla.
    • StatelessWidget es un widget que no cambia una vez construido. Perfecto para pantallas y componentes sin estado dinámico.
    • build es el método que Flutter llama para construir la interfaz. Devuelve un árbol de widgets.
    • Scaffold es el esqueleto básico de una pantalla: AppBar, body, floatingActionButton, drawer...
    • La composición de widgets es el patrón central: un Center que contiene un Column que contiene varios hijos. Todo se anida, todo es un widget.

    Un ejemplo con interacción — StatefulWidget¶

    Una app real necesita reaccionar a los cambios. Para eso existe el StatefulWidget:

    import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Contador()));

class Contador extends StatefulWidget {
  const Contador({super.key});

  @override
  State<Contador> createState() => _ContadorState();
}

class _ContadorState extends State<Contador> {
  int _cuenta = 0;
  String _mensaje = '¡Empieza a contar!';

  void _incrementar() {
    setState(() {
      _cuenta++;
      if (_cuenta == 1)  _mensaje = '¡Primer clic!';
      if (_cuenta == 5)  _mensaje = '¡Vas por buen camino!';
      if (_cuenta == 10) _mensaje = '🎉 ¡Diez clics, campeón!';
      if (_cuenta > 10)  _mensaje = 'No tienes límites... 🚀';
    });
  }

  void _reiniciar() {
    setState(() {
      _cuenta = 0;
      _mensaje = '¡Empieza a contar!';
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Contador Interactivo')),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text(
              '$_cuenta',
              style: const TextStyle(fontSize: 72, fontWeight: FontWeight.bold, color: Colors.indigo),
            ),
            const SizedBox(height: 12),
            Text(
              _mensaje,
              style: const TextStyle(fontSize: 18, color: Colors.grey),
            ),
            const SizedBox(height: 32),
            Row(
              mainAxisAlignment: MainAxisAlignment.center,
              children: [
                ElevatedButton.icon(
                  onPressed: _incrementar,
                  icon: const Icon(Icons.add),
                  label: const Text('Incrementar'),
                ),
                const SizedBox(width: 16),
                OutlinedButton.icon(
                  onPressed: _reiniciar,
                  icon: const Icon(Icons.refresh),
                  label: const Text('Reiniciar'),
                ),
              ],
            ),
          ],
        ),
      ),
    );
  }
}

    La clave aquí es setState: cuando llamas a este método, le dices a Flutter que el estado ha cambiado y que debe reconstruir el widget. Flutter lo hace de forma eficiente, reconstruyendo solo lo necesario.

    Consejos y buenas prácticas para empezar bien¶

    Antes de entrar en materia, hay algunos hábitos que marcan la diferencia entre un código Flutter que crece bien y uno que se convierte en un laberinto a las tres semanas.

    1. Organiza tu proyecto desde el principio¶

    Una estructura de carpetas clara es la diferencia entre un proyecto mantenible y un cajón de sastre:

    lib/
├── main.dart
├── app.dart               # Configuración de MaterialApp/CupertinoApp
├── core/                  # Utilidades, constantes, temas
│   ├── theme.dart
│   └── constants.dart
├── features/              # Cada funcionalidad en su carpeta
│   ├── auth/
│   │   ├── screens/
│   │   ├── widgets/
│   │   └── providers/
│   └── home/
│       ├── screens/
│       └── widgets/
└── shared/                # Widgets reutilizables entre features
    └── widgets/

    No tienes que seguir esta estructura al pie de la letra, pero tener una lógica clara desde el inicio te ahorrará muchos dolores de cabeza.

    2. Extrae widgets cuando el árbol crece¶

    Es muy tentador meter todo en el método build de una pantalla. Resiste esa tentación. Si un bloque de widgets tiene sentido por sí solo, extráelo a su propia clase:

    // ❌ Un build con 150 líneas es difícil de mantener
Widget build(BuildContext context) {
  return Column(children: [ /* 150 líneas aquí */ ]);
}

// ✅ Extraer componentes con nombre descriptivo
Widget build(BuildContext context) {
  return Column(children: [
    const _CabeceraPerfil(),
    const _ListaDeActividad(),
    const _BotonAccion(),
  ]);
}

    3. const donde puedas¶

    Marcar un widget como const le dice a Flutter que nunca va a cambiar, lo que permite optimizaciones importantes. El analizador de Dart te avisa cuando puedes añadir const y no lo has hecho:

    // ✅ Si el widget no depende de ningún valor dinámico, usa const
const Text('Título fijo')
const SizedBox(height: 16)
const Icon(Icons.home)

    4. Empieza con código, complementa con herramientas visuales¶

    Herramientas como FlutterFlow son fantásticas para prototipar rápido, pero aprender Flutter desde el código te da un control mucho más profundo. La recomendación es aprender primero cómo funcionan los widgets a mano, y luego usar las herramientas visuales para acelerar el trabajo cuando ya tienes esa base.

    5. La documentación oficial es excelente — úsala¶

    Flutter tiene una de las mejores documentaciones de cualquier framework. El catálogo de widgets y los codelabs son recursos de primer nivel que complementan perfectamente esta guía.
