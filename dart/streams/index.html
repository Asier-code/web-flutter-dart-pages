    Streams en Dart¶

    📄 Nota: Esta página, como el resto de contenidos de esta guía, proviene de un fichero de texto Markdown. Puedes encontrarla, editarla y versionarla junto al resto de la documentación sin ninguna complicación. La idea es que la guía crezca y se mantenga actualizada de forma sencilla, igual que el código que documenta.

    Si ya has trabajado con Future en Dart, ya tienes la mitad del camino hecho para entender los streams. Un Future representa un valor que llegará en algún momento del futuro: haces una petición a una API, esperas, y recibes la respuesta una sola vez.

    Un Stream es diferente. En lugar de un único valor que llega una vez, un stream es una secuencia de valores que llegan a lo largo del tiempo. No uno, sino muchos. Uno detrás de otro, cuando estén listos.

    Piensa en un stream como en el agua de un grifo: no recibes toda el agua de golpe, sino un flujo continuo que puedes ir consumiendo a medida que llega. Puedes escucharlo, pausarlo, transformarlo o cerrarlo cuando ya no lo necesites.

    ¿Cuándo aparecen los streams en la práctica?¶

    Antes de entrar en la teoría, vale la pena ver dónde te vas a encontrar streams en el mundo real, porque están en más sitios de los que parece:

    • Lecturas de ficheros grandes — en lugar de cargar todo el fichero en memoria de golpe, los datos llegan en trozos.
    • Conexiones en tiempo real — como un chat o un marcador deportivo que se actualiza solo.
    • Eventos del usuario — cada pulsación de tecla, cada movimiento del ratón puede modelarse como un stream de eventos.
    • Datos de sensores — la posición GPS de un dispositivo, que cambia continuamente.
    • Firebase y bases de datos reactivas — cuando escuchas cambios en Firestore, lo que recibes internamente es un stream.

    En todos esos casos, la característica común es la misma: los datos no llegan de una vez, llegan poco a poco, y tú tienes que estar preparado para recibirlos cuando lleguen.

    La anatomía de un stream¶

    Un stream tiene tres partes que siempre aparecen juntas:

    • El productor — quien crea y emite los datos. Puede ser un fichero, una conexión de red, un temporizador o tú mismo desde el código.
    • El stream en sí — el canal por el que fluyen los datos. Es el objeto Stream<T> de Dart, donde T es el tipo de datos que transporta.
    • El consumidor — quien escucha el stream y hace algo con cada valor que llega.

    La relación entre los tres es siempre la misma: el productor emite, el stream transporta, y el consumidor reacciona.

    Escuchando un stream: el listener¶

    La forma más directa de consumir un stream es con el método listen. Le pasas una función y esa función se ejecuta cada vez que el stream emite un nuevo valor:

    final stream = Stream<int>.periodic(
  Duration(seconds: 1),
  (i) => i,
).take(5);

stream.listen((valor) {
  print('Recibido: $valor');
});

    Este stream emite un número cada segundo durante cinco segundos. La función que le pasas a listen se ejecuta cada vez que llega un valor nuevo. No tienes que hacer nada especial para esperar: Dart se encarga de llamarla en el momento adecuado.

    listen también acepta callbacks opcionales para manejar errores y para saber cuándo el stream ha terminado:

    stream.listen(
  (valor) => print('Valor: $valor'),
  onError: (error) => print('Error: $error'),
  onDone: () => print('Stream cerrado'),
);

    El onDone es especialmente útil cuando necesitas saber que ya no van a llegar más datos y puedes liberar recursos o actualizar la interfaz.

    Streams asíncronos y async*¶

    Dart tiene una forma muy elegante de crear streams propios usando funciones asíncronas generadoras. Se definen con async* y emiten valores con la palabra clave yield:

    Stream<String> mensajes() async* {
  await Future.delayed(Duration(seconds: 1));
  yield 'Primer mensaje';

  await Future.delayed(Duration(seconds: 2));
  yield 'Segundo mensaje';

  await Future.delayed(Duration(seconds: 1));
  yield 'Tercer mensaje';
}

    Cada vez que el código llega a un yield, emite ese valor al stream y pausa hasta que el consumidor esté listo para el siguiente. Los await intermedios simulan trabajo asíncrono real, como una petición de red o una lectura de base de datos.

    Lo que hace esto tan legible es que el código parece secuencial aunque por dentro sea completamente asíncrono. Escribes los pasos en orden, y Dart se encarga de que todo ocurra en el momento correcto.

    Consumiendo streams con await for¶

    Además de listen, hay una forma de consumir streams que resulta especialmente clara cuando estás dentro de una función asíncrona: el bucle await for.

    Future<void> leerMensajes() async {
  await for (final mensaje in mensajes()) {
    print(mensaje);
  }
  print('Todos los mensajes recibidos');
}

    El bucle espera cada valor del stream, lo procesa y pasa al siguiente. Cuando el stream se cierra, el bucle termina y la ejecución continúa con la línea siguiente. Es más parecido a leer una lista que a trabajar con callbacks, lo que lo hace más fácil de seguir.

    Streams de un solo suscriptor vs. streams de difusión¶

    Hay algo importante que conviene saber antes de empezar a usar streams en proyectos reales: por defecto, un stream en Dart solo puede tener un suscriptor a la vez.

    Si intentas llamar a listen dos veces sobre el mismo stream, obtendrás un error. Esto es así porque la mayoría de streams están pensados para ser consumidos una sola vez, como la lectura de un fichero.

    Cuando necesitas que varios consumidores escuchen el mismo stream simultáneamente, puedes crear un broadcast stream:

    final controller = StreamController<int>.broadcast();

    Los streams de difusión permiten múltiples suscriptores. Son los que normalmente se usan en Flutter cuando quieres notificar cambios a varias partes de la interfaz al mismo tiempo.

    Una nota sobre los StreamControllers¶

    Aunque no es el objetivo principal de esta página, merece la pena mencionar brevemente el StreamController, porque lo verás mucho en código Flutter real.

    Un StreamController es esencialmente un stream que tú controlas manualmente: decides cuándo emitir valores, cuándo emitir errores y cuándo cerrarlo. Es la herramienta que usas cuando el stream no viene de una fuente externa (como Firebase o un sensor) sino que lo creas tú mismo para coordinar partes de tu app.

    No profundizamos aquí porque daría para una página entera. Pero cuando veas StreamController en el código de alguien, ya sabes qué es: alguien que está construyendo su propio canal de datos.

    Lo que es importante llevarse¶

    Los streams son uno de esos conceptos que al principio parecen más complicados de lo que son. Una vez que los ves en acción unas cuantas veces, se vuelven muy naturales. Lo fundamental es esto:

    • Un stream es una secuencia de valores que llegan a lo largo del tiempo, no de golpe.
    • Puedes escucharlo con listen o recorrerlo con await for, según el contexto.
    • Puedes crear tus propios streams con funciones marcadas con async* y yield.
    • Por defecto, un stream solo admite un suscriptor; si necesitas varios, usa un broadcast stream.

    Cuando empieces a trabajar con Flutter y te encuentres conectando una app a Firebase o escuchando cambios en tiempo real, ya tendrás la base para entender lo que está pasando por debajo.
