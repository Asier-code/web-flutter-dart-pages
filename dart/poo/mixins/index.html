    Mixins en Dart¶

    📄 Nota: Esta página forma parte de la guía completa Dart & Flutter. Todo el contenido proviene de ficheros de texto Markdown, lo que nos permite mantener la documentación versionada, colaborativa y fácil de actualizar con Git.

    Hay una situación que aparece constantemente en el desarrollo: tienes clases que no tienen nada que ver entre sí, pero comparten una capacidad concreta. Un Pato puede volar y nadar. Un Hidroavión también puede volar y nadar. Pero un pato no es un hidroavión, y un hidroavión no es un pato. Usar herencia aquí sería forzado y artificial.

    Para esto existen los mixins: una forma de empaquetar comportamiento reutilizable y "mezclarlo" en cualquier clase que lo necesite, sin crear jerarquías artificiales.

    ¿Qué es un mixin?¶

    Un mixin es un bloque de código (propiedades y métodos) que puede añadirse a una clase sin usar herencia. Piensa en ellos como módulos de capacidades: defines una vez la capacidad de "loggear", de "serializar a JSON" o de "validar datos", y luego la pegas en cualquier clase que la necesite.

    La diferencia clave con la herencia:

    Herencia (extends) Mixin (with)
    Relación "es un tipo de" "tiene la capacidad de"
    Cantidad Solo una superclase Múltiples mixins
    Propósito Especializar un tipo Añadir funcionalidad ortogonal
    Instanciación La superclase puede instanciarse El mixin no se instancia solo

    En Dart, los mixins se declaran con la palabra clave mixin y se aplican con with:

    mixin NombreMixin {
  void hacerAlgo() {
    print('Haciendo algo...');
  }
}

class MiClase with NombreMixin {
  // MiClase ahora tiene `hacerAlgo()` disponible
}

    Tu primer mixin — Un ejemplo sencillo¶

    Vamos a construir algo que tiene sentido en cualquier proyecto real: un sistema de logging. Muchas clases necesitan registrar lo que hacen, pero no tiene sentido que todas hereden de una clase Logger.

    // ─── MIXIN ────────────────────────────────────────────────
mixin Logger {
  // El mixin puede acceder a `runtimeType` porque todo objeto lo tiene
  void log(String mensaje) {
    final hora = DateTime.now();
    final tiempo = '${hora.hour.toString().padLeft(2, "0")}:${hora.minute.toString().padLeft(2, "0")}:${hora.second.toString().padLeft(2, "0")}';
    print('[$tiempo] [$runtimeType] $mensaje');
  }

  void logError(String mensaje) {
    print('❌ [$runtimeType] ERROR: $mensaje');
  }

  void logExito(String mensaje) {
    print('✅ [$runtimeType] $mensaje');
  }
}

// ─── CLASES QUE USAN EL MIXIN ─────────────────────────────
class ServicioDeUsuarios with Logger {
  final List<String> _usuarios = [];

  void registrar(String nombre) {
    log('Intentando registrar a "$nombre"...');
    if (nombre.isEmpty) {
      logError('El nombre no puede estar vacío.');
      return;
    }
    _usuarios.add(nombre);
    logExito('"$nombre" registrado correctamente. Total: ${_usuarios.length}');
  }

  void listar() {
    log('Listando ${_usuarios.length} usuario(s)...');
    _usuarios.forEach((u) => print('   · $u'));
  }
}

class ServicioDeProductos with Logger {
  final Map<String, double> _catalogo = {};

  void agregarProducto(String nombre, double precio) {
    log('Añadiendo producto: "$nombre" a ${precio.toStringAsFixed(2)} €');
    _catalogo[nombre] = precio;
    logExito('Producto "$nombre" añadido al catálogo.');
  }

  void mostrarCatalogo() {
    log('Mostrando catálogo con ${_catalogo.length} producto(s).');
    _catalogo.forEach((nombre, precio) {
      print('   · $nombre — ${precio.toStringAsFixed(2)} €');
    });
  }
}

// ─── MAIN ─────────────────────────────────────────────────
void main() {
  print('── Servicio de Usuarios ───────────────');
  final usuarios = ServicioDeUsuarios();
  usuarios.registrar('Ana Torres');
  usuarios.registrar('');
  usuarios.registrar('Luis García');
  usuarios.listar();

  print('\n── Servicio de Productos ──────────────');
  final productos = ServicioDeProductos();
  productos.agregarProducto('Laptop Pro', 1299.99);
  productos.agregarProducto('Ratón Inalámbrico', 34.99);
  productos.mostrarCatalogo();
}

    Fíjate en lo que ha pasado: ServicioDeUsuarios y ServicioDeProductos no tienen ninguna relación entre sí, no comparten una superclase, pero las dos tienen log, logError y logExito disponibles. El mixin Logger se "pegó" en ambas sin forzar ninguna jerarquía artificial.

    Usando varios mixins a la vez¶

    Aquí es donde los mixins brillan de verdad. Una clase puede aplicar múltiples mixins separados por coma, acumulando capacidades como si fueran piezas de LEGO.

    // ─── MIXIN 1: Validación ──────────────────────────────────
mixin Validable {
  final List<String> _errores = [];

  bool get esValido => _errores.isEmpty;
  List<String> get errores => List.unmodifiable(_errores);

  void agregarError(String error) => _errores.add(error);
  void limpiarErrores() => _errores.clear();

  void mostrarErrores() {
    if (esValido) {
      print('✅ Sin errores de validación.');
    } else {
      print('❌ Errores encontrados:');
      _errores.forEach((e) => print('   • $e'));
    }
  }
}

// ─── MIXIN 2: Serialización ───────────────────────────────
mixin Serializable {
  // Cada clase que use este mixin debe implementar este método
  Map<String, dynamic> toJson();

  String toJsonString() {
    final mapa = toJson();
    final pares = mapa.entries.map((e) => '"${e.key}": "${e.value}"');
    return '{${pares.join(', ')}}';
  }

  void imprimirJson() {
    print('📄 JSON: ${toJsonString()}');
  }
}

// ─── MIXIN 3: Auditoría ───────────────────────────────────
mixin Auditable {
  DateTime? _creadoEn;
  DateTime? _modificadoEn;
  String? _creadoPor;

  void registrarCreacion(String autor) {
    _creadoEn = DateTime.now();
    _creadoPor = autor;
    print('🕐 Creado por "$autor" el ${_formatearFecha(_creadoEn!)}');
  }

  void registrarModificacion() {
    _modificadoEn = DateTime.now();
    print('✏️  Modificado el ${_formatearFecha(_modificadoEn!)}');
  }

  void mostrarAuditoria() {
    print('── Auditoría ──────────────────────');
    print('   Creado por: ${_creadoPor ?? "desconocido"}');
    print('   Creado en:  ${_creadoEn != null ? _formatearFecha(_creadoEn!) : "—"}');
    print('   Modificado: ${_modificadoEn != null ? _formatearFecha(_modificadoEn!) : "nunca"}');
  }

  String _formatearFecha(DateTime dt) =>
      '${dt.day.toString().padLeft(2, "0")}/${dt.month.toString().padLeft(2, "0")}/${dt.year} '
      '${dt.hour.toString().padLeft(2, "0")}:${dt.minute.toString().padLeft(2, "0")}';
}

// ─── CLASE QUE COMBINA LOS TRES MIXINS ────────────────────
class Articulo with Validable, Serializable, Auditable {
  String titulo;
  String contenido;
  String autor;
  bool publicado;

  Articulo({
    required this.titulo,
    required this.contenido,
    required this.autor,
    this.publicado = false,
  });

  void validar() {
    limpiarErrores();
    if (titulo.isEmpty)      agregarError('El título no puede estar vacío.');
    if (titulo.length < 5)   agregarError('El título debe tener al menos 5 caracteres.');
    if (contenido.isEmpty)   agregarError('El contenido no puede estar vacío.');
    if (autor.isEmpty)       agregarError('El autor es obligatorio.');
    mostrarErrores();
  }

  void publicar() {
    validar();
    if (!esValido) {
      print('🚫 No se puede publicar: hay errores de validación.');
      return;
    }
    publicado = true;
    registrarModificacion();
    print('🚀 Artículo "$titulo" publicado con éxito.');
  }

  // Requerido por el mixin Serializable
  @override
  Map<String, dynamic> toJson() => {
    'titulo':    titulo,
    'autor':     autor,
    'publicado': publicado.toString(),
  };
}

// ─── MAIN ─────────────────────────────────────────────────
void main() {
  print('═══════════════════════════════════════');
  print('  SISTEMA DE GESTIÓN DE ARTÍCULOS');
  print('═══════════════════════════════════════\n');

  final articulo = Articulo(
    titulo:    'Mixins en Dart: guía práctica',
    contenido: 'Los mixins son una herramienta poderosa...',
    autor:     'Elena Martínez',
  );

  // Capacidad de Auditable
  articulo.registrarCreacion('Elena Martínez');

  print('');

  // Capacidad de Validable + publicar
  articulo.publicar();

  print('');

  // Capacidad de Serializable
  articulo.imprimirJson();

  print('');

  // Probar con un artículo inválido
  print('── Artículo inválido ──────────────────');
  final articuloMalo = Articulo(titulo: 'Hi', contenido: '', autor: '');
  articuloMalo.validar();

  print('');

  // Auditoría completa
  articulo.mostrarAuditoria();
}

    Este ejemplo muestra lo más interesante de los mixins: la clase Articulo tiene tres capacidades completamente independientes (Validable, Serializable, Auditable), cada una desarrollada y testeable por separado, y se combinan en una sola clase con with Validable, Serializable, Auditable. Sin herencia múltiple, sin complicaciones.

    Restringir un mixin con on¶

    A veces un mixin tiene sentido solo para ciertos tipos de clases. Por ejemplo, un mixin ConexionDB solo debería usarse en clases que sean servicios. Para esto, Dart permite restringir con on:

    class Repositorio {
  String nombreTabla;
  Repositorio(this.nombreTabla);
}

// Este mixin SOLO puede usarse en clases que extiendan Repositorio
mixin ConsultasAvanzadas on Repositorio {
  void buscarPorId(int id) {
    // Puede acceder a `nombreTabla` porque sabe que la clase es un Repositorio
    print('SELECT * FROM $nombreTabla WHERE id = $id');
  }

  void contarRegistros() {
    print('SELECT COUNT(*) FROM $nombreTabla');
  }
}

class UsuarioRepositorio extends Repositorio with ConsultasAvanzadas {
  UsuarioRepositorio() : super('usuarios');

  void encontrarAdmins() {
    print('SELECT * FROM $nombreTabla WHERE rol = "admin"');
  }
}

void main() {
  final repo = UsuarioRepositorio();
  repo.buscarPorId(42);       // del mixin
  repo.contarRegistros();     // del mixin
  repo.encontrarAdmins();     // propio de la clase
}

    💡 Tip: La restricción con on es útil cuando el mixin necesita acceder a propiedades o métodos que solo existen en un tipo concreto. Sin on, el mixin no puede asumir nada sobre la clase que lo usa.

    Mixins vs Herencia — ¿Cuándo usar cada uno?¶

    Esta es la pregunta del millón. Aquí va una guía práctica:

    Usa herencia (extends) cuando: - La relación entre clases es claramente "es un tipo de" (Perro es un Animal) - La subclase es una especialización de la superclase - Quieres reutilizar y potencialmente sobreescribir una implementación base completa

    Usa mixins (with) cuando: - Quieres añadir una capacidad a una clase, no definir su tipo - La misma funcionalidad se necesita en clases que no comparten jerarquía - Quieres combinar varias fuentes de comportamiento - La funcionalidad es ortogonal al tipo principal de la clase

    ¿Puedo decir "X es un tipo de Y"?
├── Sí  → Herencia (extends)
└── No  → ¿"X tiene la capacidad de Y"?
          ├── Sí → Mixin (with)
          └── No → Composición (la clase Y como propiedad)

    Consejos y buenas prácticas¶

    1. Nómbralos como capacidades o roles, no como tipos¶

    Un buen nombre de mixin describe lo que aporta, no lo que es. Esto hace que el with se lea como inglés natural:

    // ✅ Nombres que describen la capacidad
mixin Loggable { ... }
mixin Cacheable { ... }
mixin Serializable { ... }
mixin Validable { ... }

// ❌ Nombres que suenan a clase o tipo
mixin LoggerClass { ... }
mixin BaseData { ... }

    2. Mantén cada mixin enfocado en una sola responsabilidad¶

    Un mixin que hace logging, validación y serialización a la vez deja de ser reutilizable. Cuanto más pequeño y enfocado, más lugares podrás usarlo.

    // ✅ Un mixin, una capacidad
mixin Loggable { void log(String msg) { ... } }
mixin Cacheable { void cachear() { ... } }

// ❌ Mixin que intenta hacer demasiado
mixin UtilsMixin {
  void log() { ... }
  void cachear() { ... }
  void validar() { ... }
  void serializar() { ... }
}

    3. Cuidado con el orden de los mixins¶

    Cuando aplicas varios mixins, el orden importa si dos de ellos definen el mismo método. Dart resuelve los conflictos usando el último mixin de la lista (el más a la derecha) como prioritario:

    mixin A {
  void saludar() => print('Hola desde A');
}

mixin B {
  void saludar() => print('Hola desde B');
}

class MiClase with A, B {
  // B es el último, así que B.saludar() tiene prioridad
}

void main() {
  MiClase().saludar(); // Imprime: "Hola desde B"
}

    4. No uses mixins para sustituir la inyección de dependencias¶

    Los mixins son buenos para comportamiento genérico y sin estado externo, pero si necesitas configuración, servicios o dependencias externas, la composición o la inyección de dependencias son mejores opciones.

    5. Usa on para mixins que solo tienen sentido en ciertos contextos¶

    Si tu mixin accede a propiedades que solo existen en un tipo concreto, restríngelo con on. Así el compilador te avisa si alguien lo aplica donde no toca.

    // ✅ El mixin solo se puede usar en clases que extiendan Widget
mixin AnimacionMixin on Widget {
  void animar() {
    // puede acceder a propiedades de Widget
  }
}
