    Introducción a la POO en Dart¶

    📄 Nota: Esta página forma parte de la guía completa Dart & Flutter. Todo el contenido proviene de ficheros de texto Markdown, lo que garantiza una documentación mantenible, versionable y colaborativa mediante control de versiones (Git).

    ¿Qué es la Programación Orientada a Objetos?¶

    La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el código en torno a objetos: entidades que combinan datos (propiedades) y comportamiento (métodos) en una sola unidad cohesionada.

    En lugar de pensar en el programa como una lista de instrucciones, la POO nos invita a modelar el mundo real: un Usuario tiene un nombre y puede iniciar sesión; un Producto tiene un precio y puede aplicar descuentos; un Coche tiene marca y puede acelerar.

    ¿Por qué usar POO?¶

    • Organización: el código se estructura en unidades con responsabilidades claras.
    • Reutilización: las clases pueden heredarse y extenderse sin reescribir lógica.
    • Mantenibilidad: modificar una clase no afecta al resto del sistema si la interfaz se mantiene.
    • Modelado natural: el código refleja conceptos del dominio real del problema.
    • Escalabilidad: proyectos grandes se gestionan mejor cuando el código está bien encapsulado.

    POO en Dart¶

    Dart es un lenguaje orientado a objetos puro: todo en Dart es un objeto, incluyendo los números, las funciones y el valor null. Dart implementa los cuatro pilares clásicos de la POO:

    Pilar Descripción
    Encapsulación Ocultar detalles internos y exponer solo lo necesario
    Herencia Una clase puede extender otra y reutilizar su comportamiento
    Polimorfismo Un objeto puede tomar múltiples formas según su contexto
    Abstracción Modelar conceptos complejos con interfaces y clases abstractas

    Clases y Objetos¶

    ¿Qué es una clase?¶

    Una clase es una plantilla o molde que define la estructura y el comportamiento de un tipo de objeto. Especifica qué propiedades tendrá y qué acciones podrá realizar.

    ¿Qué es un objeto?¶

    Un objeto es una instancia concreta de una clase. Si la clase es el plano de un edificio, el objeto es el edificio construido a partir de ese plano. Puedes crear tantos objetos como necesites a partir de una misma clase.

    Clase  →  Plantilla / Molde
Objeto →  Instancia concreta creada a partir de la clase

    Sintaxis básica en Dart¶

    // Definición de la clase
class NombreDeLaClase {
  // Propiedades (atributos)
  tipo nombrePropiedad;

  // Constructor
  NombreDeLaClase(this.nombrePropiedad);

  // Métodos
  void hacerAlgo() {
    // lógica
  }
}

// Creación de un objeto (instancia)
var objeto = NombreDeLaClase(valor);

    Propiedades y Métodos¶

    Las propiedades almacenan el estado del objeto y los métodos definen su comportamiento.

    class Producto {
  // Propiedades
  String nombre;
  double precio;
  int stock;

  // Constructor
  Producto({required this.nombre, required this.precio, required this.stock});

  // Métodos
  void mostrarInfo() {
    print('📦 $nombre — ${precio.toStringAsFixed(2)} € (stock: $stock)');
  }

  bool estaDisponible() => stock > 0;

  void vender(int cantidad) {
    if (cantidad > stock) {
      print('⚠️  Stock insuficiente. Solo quedan $stock unidades.');
    } else {
      stock -= cantidad;
      print('✅ Venta de $cantidad x "$nombre" registrada. Stock restante: $stock');
    }
  }

  double calcularDescuento(double porcentaje) {
    return precio * (1 - porcentaje / 100);
  }
}

void main() {
  // Crear objetos (instancias) de la clase Producto
  Producto laptop = Producto(nombre: 'Laptop Pro', precio: 1299.99, stock: 10);
  Producto raton  = Producto(nombre: 'Ratón Inalámbrico', precio: 34.99, stock: 3);

  // Usar propiedades y métodos
  laptop.mostrarInfo();
  raton.mostrarInfo();

  print('\n¿Laptop disponible? ${laptop.estaDisponible()}');

  laptop.vender(3);
  raton.vender(5); // Excede el stock

  double precioConDto = laptop.calcularDescuento(15);
  print('\n💰 Laptop con 15% de descuento: ${precioConDto.toStringAsFixed(2)} €');
}

    Constructores¶

    El constructor es un método especial que se ejecuta al crear un objeto. Se encarga de inicializar sus propiedades con los valores iniciales.

    Tipos de constructores en Dart¶

    class Usuario {
  String nombre;
  String email;
  String rol;
  bool activo;

  // 1. Constructor generativo estándar
  Usuario(this.nombre, this.email, this.rol, this.activo);

  // 2. Constructor con parámetros nombrados
  Usuario.nombrado({
    required this.nombre,
    required this.email,
    this.rol = 'usuario',
    this.activo = true,
  });

  // 3. Constructor nombrado (factory alternativa)
  Usuario.administrador({required this.nombre, required this.email})
    : rol = 'admin',
      activo = true;

  // 4. Constructor factory (lógica personalizada de creación)
  factory Usuario.desdeJson(Map<String, dynamic> json) {
    return Usuario.nombrado(
      nombre: json['nombre'] as String,
      email:  json['email']  as String,
      rol:    json['rol']    as String? ?? 'usuario',
      activo: json['activo'] as bool?   ?? true,
    );
  }

  @override
  String toString() => '[$rol] $nombre <$email> — ${activo ? "activo" : "inactivo"}';
}

void main() {
  // Usando el constructor nombrado
  var u1 = Usuario.nombrado(nombre: 'Ana López', email: 'ana@ejemplo.com');

  // Usando el constructor especializado
  var u2 = Usuario.administrador(nombre: 'Carlos Ruiz', email: 'carlos@ejemplo.com');

  // Usando el factory constructor con datos JSON (típico de APIs)
  var u3 = Usuario.desdeJson({
    'nombre': 'Marta Gil',
    'email': 'marta@ejemplo.com',
    'rol': 'editor',
    'activo': false,
  });

  print('👤 $u1');
  print('👤 $u2');
  print('👤 $u3');
}

    Encapsulación¶

    La encapsulación consiste en ocultar los detalles internos de una clase y exponer solo lo que el código externo necesita. En Dart, los miembros privados se marcan con un guion bajo (_) como prefijo y solo son accesibles dentro del mismo fichero.

    Para exponer datos de forma controlada se usan los getters y setters.

    class CuentaBancaria {
  final String titular;
  double _saldo; // privado: no accesible directamente desde fuera

  CuentaBancaria({required this.titular, double saldoInicial = 0.0})
      : _saldo = saldoInicial;

  // Getter: permite leer el saldo sin poder modificarlo directamente
  double get saldo => _saldo;

  // Getter calculado
  String get estado => _saldo >= 0 ? '🟢 Al corriente' : '🔴 En descubierto';

  // Métodos que controlan cómo se modifica el saldo
  void ingresar(double cantidad) {
    if (cantidad <= 0) throw ArgumentError('La cantidad debe ser positiva.');
    _saldo += cantidad;
    print('✅ Ingreso de ${cantidad.toStringAsFixed(2)} €. Nuevo saldo: ${_saldo.toStringAsFixed(2)} €');
  }

  void retirar(double cantidad) {
    if (cantidad <= 0) throw ArgumentError('La cantidad debe ser positiva.');
    if (cantidad > _saldo) {
      print('⚠️  Fondos insuficientes. Saldo actual: ${_saldo.toStringAsFixed(2)} €');
      return;
    }
    _saldo -= cantidad;
    print('💸 Retirada de ${cantidad.toStringAsFixed(2)} €. Nuevo saldo: ${_saldo.toStringAsFixed(2)} €');
  }

  @override
  String toString() => 'Cuenta de $titular | Saldo: ${_saldo.toStringAsFixed(2)} € | $estado';
}

void main() {
  var cuenta = CuentaBancaria(titular: 'Elena Martínez', saldoInicial: 1000.0);

  print(cuenta);
  cuenta.ingresar(500.0);
  cuenta.retirar(200.0);
  cuenta.retirar(2000.0); // Fondos insuficientes

  // El saldo es accesible (getter), pero no modificable directamente
  print('\nSaldo actual: ${cuenta.saldo} €');
  print('Estado: ${cuenta.estado}');

  // cuenta._saldo = 999999; // ❌ Error: miembro privado
}

    Herencia, Mixins e Interfaces — Introducción¶

    Dart ofrece tres mecanismos para compartir y reutilizar comportamiento entre clases. Se estudian en detalle en sus propias secciones de esta guía, pero aquí tienes una introducción rápida:

    Herencia — extends¶

    Una clase puede heredar de otra, reutilizando sus propiedades y métodos y añadiendo o sobreescribiendo los que necesite.

    class Animal {
  String nombre;
  Animal(this.nombre);

  void respirar() => print('$nombre respira.');
}

class Perro extends Animal {
  String raza;
  Perro(super.nombre, this.raza);

  void ladrar() => print('$nombre dice: ¡Guau!');

  @override
  String toString() => 'Perro($nombre, $raza)';
}

void main() {
  var perro = Perro('Rex', 'Labrador');
  perro.respirar(); // Heredado de Animal
  perro.ladrar();   // Propio de Perro
  print(perro);
}

    Mixins — with¶

    Los mixins permiten añadir comportamiento a una clase sin usar herencia. Son ideales para compartir funcionalidades entre clases que no comparten jerarquía.

    mixin Volador {
  void volar() => print('$this está volando 🦅');
}

mixin Nadador {
  void nadar() => print('$this está nadando 🐟');
}

class Pato with Volador, Nadador {
  final String nombre;
  Pato(this.nombre);

  @override
  String toString() => 'Pato($nombre)';
}

void main() {
  var pato = Pato('Donald');
  pato.volar();
  pato.nadar();
}

    Interfaces — implements¶

    En Dart, cualquier clase puede actuar como interfaz. Al usar implements, la clase implementadora debe definir todos los métodos y propiedades de la clase o interfaz original.

    abstract class Autenticable {
  bool iniciarSesion(String password);
  void cerrarSesion();
}

class UsuarioApp implements Autenticable {
  final String email;
  final String _password;
  bool _sesionActiva = false;

  UsuarioApp(this.email, this._password);

  @override
  bool iniciarSesion(String password) {
    _sesionActiva = password == _password;
    print(_sesionActiva ? '✅ Sesión iniciada' : '❌ Contraseña incorrecta');
    return _sesionActiva;
  }

  @override
  void cerrarSesion() {
    _sesionActiva = false;
    print('👋 Sesión cerrada para $email');
  }
}

void main() {
  var usuario = UsuarioApp('ana@ejemplo.com', 'secreto123');
  usuario.iniciarSesion('wrongpass');
  usuario.iniciarSesion('secreto123');
  usuario.cerrarSesion();
}

    Resumen comparativo¶

    Mecanismo Palabra clave ¿Herencia de implementación? ¿Múltiple? Uso típico
    Herencia extends ✅ Sí ❌ Una sola Relación "es un tipo de"
    Mixin with ✅ Sí ✅ Múltiple Añadir capacidades ortogonales
    Interfaz implements ❌ Solo contrato ✅ Múltiple Garantizar una API específica

    Buenas Prácticas con Clases y Objetos¶

    1. Una clase, una responsabilidad (SRP)¶

    // ❌ Clase con demasiadas responsabilidades
class Usuario {
  void guardarEnBaseDeDatos() { ... }
  void enviarEmail() { ... }
  void generarPDF() { ... }
}

// ✅ Responsabilidades separadas
class Usuario { ... }
class UsuarioRepositorio { void guardar(Usuario u) { ... } }
class EmailService { void enviar(String destino) { ... } }

    2. Usa final para propiedades inmutables¶

    class Punto {
  // ✅ Las coordenadas no cambian tras la creación
  final double x;
  final double y;

  const Punto(this.x, this.y);

  double distanciaAlOrigen() => (x * x + y * y);
}

    3. Prefiere constructores nombrados para claridad semántica¶

    // ✅ El nombre del constructor comunica el contexto de creación
var admin    = Usuario.administrador(nombre: 'Ana');
var invitado = Usuario.invitado();
var desdeApi = Usuario.desdeJson(jsonData);

    4. Sobreescribe toString para facilitar la depuración¶

    // ✅ Facilita el debug y el logging
@override
String toString() => 'Producto(nombre: $nombre, precio: $precio)';

    5. Usa const en constructores cuando todos los valores son conocidos en compilación¶

    class Color {
  final int r, g, b;
  const Color(this.r, this.g, this.b);
}

// ✅ Objeto creado en tiempo de compilación, más eficiente
const rojo  = Color(255, 0, 0);
const verde = Color(0, 255, 0);

    6. Nombra las clases en PascalCase y los miembros en camelCase¶

    // ✅ Convenciones de Dart
class GestorDeInventario {        // PascalCase para la clase
  int totalProductos = 0;         // camelCase para propiedades
  void agregarProducto() { ... }  // camelCase para métodos
}
