    Clases y Objetos en Dart¶

    📄 Nota: Esta página forma parte de la guía completa Dart & Flutter. Todo el contenido proviene de ficheros de texto Markdown, lo que nos permite mantener la documentación versionada, colaborativa y fácil de actualizar con Git.

    Si vienes de otro lenguaje orientado a objetos como Java, Kotlin o Swift, muchas cosas te van a resultar familiares. Y si es tu primera vez con POO, no te preocupes: vamos paso a paso. Las clases son uno de esos conceptos que, cuando los entiendes bien, cambian completamente la forma en que piensas el código.

    ¿Qué es una clase y para qué sirve?¶

    Imagina que estás construyendo una app de gestión de una biblioteca. Tienes libros, y cada libro tiene un título, un autor, un número de páginas y un estado (disponible o prestado). Podrías manejar cada libro con variables sueltas, pero eso escala fatal. En cuanto tengas 50 libros, el código se convierte en un caos.

    Aquí es donde entran las clases. Una clase es como una plantilla que describe cómo es un tipo de objeto: qué datos guarda y qué puede hacer. A partir de esa plantilla puedes crear tantas instancias (objetos) como necesites, cada una con sus propios valores.

    Clase  →  La plantilla, el molde
Objeto →  Cada ejemplar concreto creado a partir de ese molde

    En Dart, la sintaxis es limpia y directa:

    class NombreDeLaClase {
  // propiedades y métodos aquí
}

    Nada más. Sin palabras clave extrañas, sin ceremonias. Vamos a construir algo real.

    Tu primera clase en Dart¶

    Sigamos con el ejemplo de la biblioteca. Vamos a crear una clase Libro:

    class Libro {
  // Propiedades: los datos que describe cada libro
  String titulo;
  String autor;
  int paginas;
  bool disponible;

  // Constructor: cómo se crea un libro nuevo
  Libro({
    required this.titulo,
    required this.autor,
    required this.paginas,
    this.disponible = true,
  });

  // Método: algo que el libro "sabe hacer"
  void mostrarInfo() {
    String estado = disponible ? '✅ Disponible' : '📕 Prestado';
    print('$titulo — $autor ($paginas págs.) | $estado');
  }

  // Método que cambia el estado del libro
  void prestar() {
    if (!disponible) {
      print('⚠️  "$titulo" ya está prestado.');
      return;
    }
    disponible = false;
    print('📖 "$titulo" prestado con éxito.');
  }

  void devolver() {
    disponible = true;
    print('↩️  "$titulo" devuelto. Ya está disponible.');
  }
}

void main() {
  // Creamos un objeto de tipo Libro
  Libro libro1 = Libro(
    titulo: 'El Quijote',
    autor: 'Miguel de Cervantes',
    paginas: 863,
  );

  // Accedemos a sus propiedades y métodos
  libro1.mostrarInfo();
  libro1.prestar();
  libro1.mostrarInfo();
  libro1.devolver();
  libro1.mostrarInfo();
}

    Fíjate en algunas cosas de este ejemplo:

    • Las propiedades (titulo, autor, paginas, disponible) son variables declaradas directamente dentro de la clase, fuera de cualquier método.
    • El constructor usa this.propiedad como atajo para asignar los valores directamente. Es una sintaxis muy cómoda de Dart.
    • Los métodos (mostrarInfo, prestar, devolver) son funciones que pertenecen a la clase y tienen acceso directo a sus propiedades.
    • Al crear el objeto, usamos Libro(...) como si fuera una función: eso llama al constructor.

    Propiedades y Métodos en detalle¶

    Propiedades¶

    Las propiedades son las variables que pertenecen a cada objeto. Cada instancia tiene su propia copia de esos valores, independiente del resto.

    Pueden ser de cualquier tipo, incluir valores por defecto y marcarse como final si no deben cambiar tras la creación del objeto:

    class Configuracion {
  final String appName;       // No cambia nunca
  String tema;                // Puede cambiar
  int intentosMaximos;        // Con valor por defecto
  bool notificaciones;

  Configuracion({
    required this.appName,
    this.tema = 'claro',
    this.intentosMaximos = 3,
    this.notificaciones = true,
  });
}

    Métodos¶

    Los métodos son las funciones que define la clase. Pueden leer y modificar las propiedades del objeto, devolver valores o simplemente realizar acciones.

    Hay un tipo especial de método que merece mención: los getters y setters, que permiten acceder a propiedades de forma controlada:

    class Temperatura {
  double _celsius; // propiedad interna

  Temperatura(this._celsius);

  // Getter: leer el valor en Celsius
  double get celsius => _celsius;

  // Getter calculado: devuelve el equivalente en Fahrenheit
  double get fahrenheit => _celsius * 9 / 5 + 32;

  // Setter con validación
  set celsius(double valor) {
    if (valor < -273.15) {
      throw ArgumentError('No existe temperatura por debajo del cero absoluto.');
    }
    _celsius = valor;
  }
}

    Constructores en profundidad¶

    El constructor es el punto de entrada para crear objetos. Dart ofrece varias formas de definirlos, y cada una tiene su momento ideal.

    Constructor básico posicional¶

    class Punto {
  double x;
  double y;

  // Los argumentos se pasan en orden, sin nombre
  Punto(this.x, this.y);

  @override
  String toString() => 'Punto($x, $y)';
}

void main() {
  var origen = Punto(0, 0);
  var p1     = Punto(3.5, -2.0);

  print(origen);
  print(p1);
}

    Constructor con parámetros nombrados¶

    Es el más habitual en Dart y el preferido para clases con más de dos propiedades, porque las llamadas son autoexplicativas:

    class Tarea {
  String titulo;
  String descripcion;
  bool completada;
  DateTime fechaCreacion;

  Tarea({
    required this.titulo,
    this.descripcion = '',
    this.completada = false,
    DateTime? fechaCreacion,
  }) : fechaCreacion = fechaCreacion ?? DateTime.now();

  @override
  String toString() => '[${completada ? "✓" : " "}] $titulo';
}

void main() {
  var t1 = Tarea(titulo: 'Revisar PRs');
  var t2 = Tarea(titulo: 'Actualizar docs', descripcion: 'Sección de colecciones');
  var t3 = Tarea(titulo: 'Deploy a producción', completada: true);

  print(t1);
  print(t2);
  print(t3);
}

    Constructores nombrados¶

    Cuando necesitas varias formas de crear un objeto, los constructores nombrados son la solución. Es un patrón muy común en Dart:

    class Color {
  final int r, g, b;

  // Constructor principal
  Color(this.r, this.g, this.b);

  // Constructor nombrado para colores predefinidos
  Color.negro() : r = 0, g = 0, b = 0;
  Color.blanco() : r = 255, g = 255, b = 255;
  Color.rojo()   : r = 255, g = 0, b = 0;

  // Constructor desde hexadecimal
  Color.desdeHex(String hex)
    : r = int.parse(hex.substring(1, 3), radix: 16),
      g = int.parse(hex.substring(3, 5), radix: 16),
      b = int.parse(hex.substring(5, 7), radix: 16);

  @override
  String toString() => 'Color(r:$r, g:$g, b:$b)';
}

void main() {
  var c1 = Color(128, 64, 255);
  var c2 = Color.negro();
  var c3 = Color.rojo();
  var c4 = Color.desdeHex('#1A73E8');

  print(c1);
  print(c2);
  print(c3);
  print(c4);
}

    Trabajando con varios objetos¶

    Ahora que ya sabes crear clases, veamos cómo se trabaja con múltiples instancias en un escenario más completo. Este es el tipo de código que escribirás en el día a día:

    class Empleado {
  final int id;
  final String nombre;
  String departamento;
  double salarioBase;

  Empleado({
    required this.id,
    required this.nombre,
    required this.departamento,
    required this.salarioBase,
  });

  double get salarioConBonus => salarioBase * 1.15;

  void asignarDepartamento(String nuevoDepartamento) {
    print('🔄 $nombre traslado: $departamento → $nuevoDepartamento');
    departamento = nuevoDepartamento;
  }

  void mostrarFicha() {
    print('─────────────────────────────');
    print('👤 Empleado #$id: $nombre');
    print('   Departamento: $departamento');
    print('   Salario base: ${salarioBase.toStringAsFixed(2)} €');
    print('   Con bonus:    ${salarioConBonus.toStringAsFixed(2)} €');
  }
}

void main() {
  // Creamos una lista de empleados
  List<Empleado> equipo = [
    Empleado(id: 1, nombre: 'Ana Torres',   departamento: 'Desarrollo', salarioBase: 38000),
    Empleado(id: 2, nombre: 'Luis Gómez',   departamento: 'Diseño',     salarioBase: 34000),
    Empleado(id: 3, nombre: 'Marta Ríos',   departamento: 'Desarrollo', salarioBase: 42000),
    Empleado(id: 4, nombre: 'Pedro Sánchez', departamento: 'QA',        salarioBase: 31000),
  ];

  // Mostrar fichas de todos
  print('📋 EQUIPO COMPLETO\n');
  equipo.forEach((e) => e.mostrarFicha());

  // Filtrar por departamento
  print('\n\n🖥️  DEPARTAMENTO DE DESARROLLO\n');
  var devs = equipo.where((e) => e.departamento == 'Desarrollo').toList();
  devs.forEach((e) => e.mostrarFicha());

  // El empleado con mayor salario base
  Empleado mejorPagado = equipo.reduce((a, b) => a.salarioBase > b.salarioBase ? a : b);
  print('\n\n🏆 Mayor salario base: ${mejorPagado.nombre} (${mejorPagado.salarioBase} €)');

  // Promedio de salarios
  double totalSalarios = equipo.fold(0, (suma, e) => suma + e.salarioBase);
  double media = totalSalarios / equipo.length;
  print('📊 Salario medio del equipo: ${media.toStringAsFixed(2)} €');

  // Trasladar a alguien
  print('');
  equipo[1].asignarDepartamento('Producto');
}

    Este ejemplo muestra algo importante: los objetos viven perfectamente dentro de colecciones (List, Map, Set), y puedes usar todos los métodos funcionales de Dart (where, reduce, fold, map…) para trabajar con ellos de forma muy expresiva.

    Consejos y buenas prácticas¶

    Llegados a este punto ya sabes crear clases y objetos. Pero escribir código que funcione es solo la mitad del trabajo; la otra mitad es escribir código que se entienda y sea fácil de mantener. Aquí van los consejos que más ayudan en el día a día:

    1. Dale a cada clase una sola responsabilidad¶

    Una clase que hace demasiadas cosas es difícil de entender, de probar y de cambiar. Si tu clase Usuario también sabe guardar en base de datos y enviar emails, algo va mal.

    // ❌ Demasiadas responsabilidades en una sola clase
class Usuario {
  void guardarEnDB() { ... }
  void enviarEmailBienvenida() { ... }
  void generarTokenJWT() { ... }
}

// ✅ Cada clase tiene una razón de existir
class Usuario { ... }
class UsuarioRepositorio { void guardar(Usuario u) { ... } }
class EmailService { void enviarBienvenida(Usuario u) { ... } }

    2. Usa final en propiedades que no deben cambiar¶

    Si una propiedad se asigna en el constructor y no debería modificarse después, márcala como final. El compilador te protegerá de cambios accidentales.

    class Factura {
  final String numero;      // ✅ No tiene sentido cambiar el número de factura
  final DateTime fecha;     // ✅ Tampoco la fecha de emisión
  double importe;           // Puede modificarse si se aplican descuentos
}

    3. Sobreescribe toString siempre que puedas¶

    Por defecto, print(objeto) muestra algo como Instance of 'Libro', que no ayuda nada. Sobreescribir toString tarda dos minutos y facilita enormemente el debug:

    @override
String toString() => 'Libro("$titulo", $autor, $paginas págs.)';

    4. Usa constructores nombrados para casos especiales¶

    En lugar de tener un constructor con 10 parámetros y flags confusos, usa constructores nombrados que expresen la intención claramente:

    // ✅ El nombre del constructor es autodocumentado
var admin    = Usuario.administrador(nombre: 'Ana');
var invitado = Usuario.invitado();
var desdeApi = Usuario.desdeJson(responseData);

    5. Mantén los métodos cortos y con un propósito claro¶

    Si un método tiene más de 20-25 líneas, probablemente puede dividirse. Los métodos pequeños son más fáciles de leer, de probar y de reutilizar.

    6. Nombra bien: PascalCase para clases, camelCase para todo lo demás¶

    class GestorDePedidos { }         // ✅ Clase en PascalCase
  int totalPedidos = 0;           // ✅ Propiedad en camelCase
  void procesarPedido() { ... }   // ✅ Método en camelCase
